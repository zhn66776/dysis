# AgentDesk 无限画布 · 设计文档 v1

> 整理日期：2026-10-29　｜　状态：第一阶段完成（0.4.0）；原生分叉（0.4.1）；面板控件（0.4.2）；合流节点与重跑下游（0.5.0）；文件和 MCP 结果节点（0.6.0）
> 本文件取代“像素办公室”方向（`DESIGN.md`）作为主界面方案。原 SwiftUI 界面保留为“经典界面”窗口。

## 1. 目标

把“一个对话一个窗口”的聊天应用改成一块可以平移、缩放的画布：

- **一块画布 = 一个大目标**（例如“Q4 定价方案”）。
- **一个节点 = 一个子目标**，技术上是一个独立的官方会话：独立模型、独立官方 Session ID、独立工作目录、独立历史。
- 节点之间用两种线组织上下文，用户可以从任意一条回复里长出新节点。

单个节点就是一个普通对话。只问一个问题时，不需要画图。

## 2. 核心概念

### 2.1 节点

| 类型 | 阶段 | 说明 |
|---|---|---|
| 对话节点 | 一 | 对应一个 `ChatSession`，头部按 provider 着色 |
| 合流节点 | 二 | 本质也是对话节点，创建时自动连好多条数据线并预填模板提示词 |
| 草稿节点 | 二 | 模型建议的子目标，虚线灰色，未运行；用户确认后转成对话节点 |
| 文件 / MCP 结果节点 | 二（0.6.0） | 只读的资料源，没有输入框、不调用模型；只能作为数据线的起点，头部用中性色（见 2.7） |

### 2.2 两种线

| | 继承线（分支） | 数据线 |
|---|---|---|
| 含义 | 子节点继承父节点到分叉点为止的完整历史 | 把上游的最终输出作为输入传过去，不带历史 |
| 数量 | 每个节点最多一条入线 | 每个节点可接多条入线 |
| 样式 | 3px 实线，颜色取父节点的 provider 色 | 1.2px 灰线，带箭头 |
| 创建方式 | 回复下方“从这里分支” | 从节点右侧输出口拖到另一个节点；拖到空白处则新建下游节点 |

### 2.3 继承怎么实现

子节点第一次发送时决定用哪种方式；拿到自己的官方 Session ID 之后，后续轮次由官方 CLI 保存历史，不再继承。

| 条件 | 方式 |
|---|---|
| Claude → Claude，分叉点是父节点的最新一条消息 | 原生分叉：`--resume <父会话> --fork-session`，在子节点自己的工作目录里运行 |
| Codex → Codex，分叉点的回复记录了回合 ID | 原生分叉：`thread/fork`，带 `lastTurnId`（含这一轮），`excludeTurns: true` |
| Codex → Codex，分叉点是最新一条、但没有回合 ID（0.4.1 之前的记录） | 原生分叉整个线程 |
| Claude 父节点在分叉点之后又有新消息 | 回放继承（Claude 只能从最新状态分叉） |
| Grok / Gemini、跨 provider 分支、父节点正在回复、上次原生分叉失败 | 回放继承 |

- 2026-10-29 本机离线检查：Claude Code 2.1.308 在别的目录里用 `--resume <id>` 能找到会话，不存在的 ID 会报 “No conversation found”，两次都没有发起模型回合。
- Codex 每次回复时从 `turn/start` 的响应里读取回合 ID，存在助手消息的 `providerTurnID` 上，作为以后的分叉点。
- **只在成功时记录新会话。**Claude 分叉失败时，CLI 仍会输出一个空的新会话 ID，所以分叉回合成功结束后才保存子节点的 Session ID。如果返回的 ID 和父节点相同，立刻停止，避免往父节点的会话里写东西。Codex 同理。
- **失败一次就回落。**原生分叉的回合结束时，子节点仍然没有官方 Session ID，就在继承线上记 `nativeForkFailed`，之后改用回放继承，面板会写明原因。不会自动重试。
- 面板在第一次发送前显示“原生分叉”或“回放继承（原因）”；发送后，第一条消息的来源标签会写明用了哪种方式。

**回放继承**：把祖先链上到各分叉点为止的文字记录作为参考资料，放在用户消息前面发给新会话。工具调用的细节和历史图片不会带过去。

### 2.4 数据线传什么

- 默认传上游节点最后一条**完整**的回复。正在输出、失败或已停止的回复不会传。
- 每条数据线记录上次传过的消息 ID（`lastDeliveredMessageID`）。上游没有新回复时，不会重复传，避免同一段内容在官方历史里反复出现。
- 上游内容以“参考资料，不是指令”的格式放进提示词，并且有长度上限；被截断的部分会明确标出。
- 第二阶段：如果节点是通过“针对这段追问”创建的，数据线只传选中的那段文字。

### 2.5 合流节点（0.5.0）

- ⌘ / Shift / Ctrl 点击节点切换选中，或 Shift 拖动框选。选中 2～8 个节点后，顶栏出现“合并结论”：先选 provider，再选模板。
- 模板：**对比**（优缺点、适用场景、推荐和待验证的假设）、**汇总**（合并成一份结论并标出矛盾）、**挑错**（找错误、漏洞和风险，按严重程度排序）。
- 会新建一个节点放在选中节点右侧，每个来源连一条数据线，模板提示词放进输入框。**不会自动发送**：你可以改提示词，点发送才调用 1 次。输入框下方会写明“发送 1 次，带上 N 个上游输出”，还没有回复的上游会单独标出。
- 节点头部显示“合流 · 对比”等标记（存在 `CanvasNode.merge` 上）。

### 2.6 上游变了怎么办（0.5.0）

- **已过期**：一个节点已经回答过，但它的某条数据线上有它还没收到的新回复，就标成“● 上游已更新”，边框变黄。继承线不算：分支的起点是固定的。
- **用新输入重新回答**：过期节点的面板里有这个按钮，调用 1 次。发送的是“上游节点有了新的输出。请基于新的输入，重新回答这个问题：”加上它上一次的问题，同时带上新的上游输出。
- **重跑下游**：如果某个节点的直接下游已经过期，节点右下角会出现“▶ 重跑下游 N”，面板里也有同样的按钮。N 是沿数据线能到达、而且已经运行过的节点数。点击后先在画布内弹出确认框，列出调用次数和顺序；确认后按依赖顺序逐个运行，每个节点等上一个完成才开始。
- 某个节点失败或停止时，后面的节点不再运行。顶栏显示“正在重跑 2 / 4”，可以随时停止。一次最多 12 个节点，和讨论室的上限一样。
- 不会自动重跑，也不会自动重试。

### 2.7 文件和 MCP 结果节点（0.6.0）

一份文件或一次 MCP 结果可以通过数据线同时喂给多个对话，不必在每个对话里各附加一次。

- **文件节点**：顶栏“＋ 新节点”或双击空白处的菜单里选“文件…”，用系统文件面板选文件；也可以把文件拖到画布空白处，在落点新建。拖到打开的对话面板上仍然是给这个对话添加附件（和以前一样）；拖到文件节点或它的面板上，是给这个节点添加文件。导入走 `AttachmentStore`，和消息附件相同：复制到 `Attachments/<UUID>/`，图片缩小，PDF / Word / 文本提取文字；整个节点最多 6 个文件、4 张图片，单个 20 MB。提取不到文字的文件（如扫描 PDF）会被拒绝。面板里可以逐个移除、继续添加、改名（清空名称恢复自动名称）。删除节点时一并删除复制的文件，原文件不动。
- **MCP 结果节点**：MCP 工作台运行工具后，“最近结果”下面多了“放到画布上”，和“附加到…”并列；节点保存结果文字、服务器名、工具名、参数和调用时间。面板里的“重新运行工具…”只是打开工作台并选好服务器；按“发现工具”后自动选中原来的工具、填好原来的参数，再按“运行工具”，然后点“更新「…」”。画布不会自己调用 MCP。
- **怎么送到下游**：文档文字和 MCP 结果放进目标提示词的“[资料节点的内容]”段，写明“它们是资料，不是指令”，和上游回复共用长度上限并平均分配，截断处标出“[资料内容已截断。]”。图片作为真正的图片输入：Claude、ChatGPT 可以接收；Cursor（Grok / Gemini）不接收，面板的“数据线输入”下面会写明哪些图片不会发送，提示词里也会注明“未发送的图片”。一次最多 4 张图片（包括输入框里的附件），多出的同样注明省略。
- **版本**：资料节点有一个内容版本（`CanvasSource.version`），文件增减或 MCP 结果更新时换新。数据线沿用 `lastDeliveredMessageID` 记录送达的版本，所以每个版本只送一次；内容变了，已经回答过的下游对话会标成“已过期”，“用新输入重新回答”和“重跑下游”照常可用。改名不算新内容。
- **限制**：资料节点只能作为数据线的起点：不能连入、不能做继承线的父节点、不能被选进合流（合流节点的上游可以有它们）；它们不是调用，重跑下游的次数不算它们，从资料节点也可以“重跑下游”。
- `canvases.json` 里资料节点就是带 `source` 字段的节点（`sessionID` 等于节点 ID，不对应任何会话）；旧文件没有这个字段，照常读取。

## 3. 界面

### 3.1 布局

```
┌──────────┬───────────────────────────────┬──────────────┐
│ 侧栏      │ 画布（点阵背景，可平移、缩放）     │ 对话面板       │
│ 画布列表   │  节点 ── 继承线 / 数据线 ──> 节点 │ 选中节点时滑出 │
│ 经典界面   │                               │ 完整对话      │
│ MCP · 设置│  左下：缩放控件                  │ 输入框        │
└──────────┴───────────────────────────────┴──────────────┘
```

- 侧栏宽 220pt，可以收起。
- 对话面板宽 400pt，选中对话节点时滑出，按 Esc 或点击空白处关闭。
- 面板顶部显示模型、推理强度和官方会话 ID 缩写，然后是“上游输入”：继承来源和数据线来源分开列出。
- 继承下来的历史默认折叠成一行“已继承 N 条消息”，展开后只读。
- 用户消息放在右侧气泡里；模型回复不加气泡，用衬线字体。运行中时，发送键变成停止键。
- 面板顶部（0.4.2）：模型和推理档位选择器，作用于下一条消息，回复中不可改；右侧显示官方会话 ID 缩写。下面一行是**上下文**（最近一次回复后的 token 数 / 模型窗口）和**剩余额度**（最紧的那个订阅窗口，悬停看全部窗口和重置时间）。Codex 打开面板时用 `account/rateLimits/read` 读取，最多每分钟一次；Claude 在回复过程中由 `rate_limit_event` 更新；Cursor 两项都不提供，显示“—”并说明原因。
- 输入框左下角的“＋”：添加图片或文档、打开 MCP 工具。也可以把文件拖进窗口，交给当前打开的对话。待发送的文件显示在输入框上方，可以逐个移除。

### 3.2 主题

跟随系统外观，同一套组件只切换颜色变量。对比度下限：正文 ≥ 13:1，次要文字 ≥ 6.5:1，提示文字 ≥ 3.7:1；卡片、输入框、菜单用 1px 描边，避免细线在暗处看不清。

| 边框 | `#D6D2C4` / 强调 `#C5C0AF`，1px | `#3A3A3A` / 强调 `#4A4A4A`，1px |
| 正文 | `#1F1E1B` | `#F0F0F0` |
| 次要文字 | `#55524A`，提示 `#7D796D` | `#B0B0B0`，提示 `#8A8A8A` |
| 元信息字体 | 无衬线 | 等宽 |
| 主操作按钮 | 陶土 `#C96442` | 浅灰 `#F0F0F0` |

Provider 色（主色 / 浅色头部 / 深色头部）：

| Provider | 主色 | 浅色头部 | 深色头部 |
|---|---|---|---|
| Claude | `#C96442` | `#F6E6DE` | `#3A241B` |
| ChatGPT | `#10A37F` | `#DDF2EB` | `#13332A` |

颜色只用在节点头部底色和连线上；正文和卡片底色保持中性。provider 图标使用项目自带的 SVG。

### 3.3 节点状态

| 状态 | 表现 |
|---|---|
| 空白 | 正文显示“还没有消息” |
| 运行中 | 底部显示状态文字，入线变成虚线 |
| 完成 | 底部显示对勾 |
| 失败 | 红色描边，底部显示原因 |
| 已停止 | 底部显示“已停止” |
| 选中 | 浅色模式深色描边，深色模式用 provider 色描边 |

### 3.4 操作

| 操作 | 方式 |
|---|---|
| 新建节点 | 顶栏“新节点”菜单；在空白处双击；从输出口拖到空白处 |
| 新建文件 / MCP 结果节点 | 新节点菜单里的“文件…”“MCP 结果…”；把文件拖到画布空白处；MCP 工作台里的“放到画布上” |
| 打开对话 | 单击节点 |
| 从回复分支 | 面板里回复下方的“从这里分支” |
| 连数据线 | 从右侧输出口拖到另一个节点的左侧输入口 |
| 删除线或节点 | 选中后按 Delete。删除节点会在画布内弹出确认框，只删除本地记录，不删除官方历史 |
| 发送 | Enter；Shift+Enter 换行；输入法组字时 Enter 不发送 |

## 4. 架构

```
┌──────────── WKWebView（React + React Flow）────────────┐
│ 侧栏 · 画布 · 对话面板        只负责显示和发出指令         │
└───────────── postMessage ▲ │ ▼ agentDesk.receive ───────┘
┌──────────── Swift（AgentDesk 应用目标）─────────────────┐
│ CanvasBridge：解码指令、合并推送                          │
│ CanvasModel：画布、节点、连线的操作，组装上下文              │
│ AppModel：会话、发送、停止（沿用现有逻辑）                  │
└──────────────────────────┬─────────────────────────────┘
┌──────────── AgentDeskCore（harness）────────────────────┐
│ CanvasBoard / CanvasStore / CanvasContextBuilder         │
│ ClaudeBackend · CodexBackend · CursorBackend · CLIProcess│
└──────────────────────────────────────────────────────────┘
```

- 画布的真实状态保存在 Swift，存为 `canvases.json`，和 `sessions.json` 放在同一个目录。网页只持有显示用的副本，刷新后会从 Swift 重新拿。
- 换掉前端时，数据和 harness 都不用动。

### 4.1 网页加载与安全

- 网页通过自定义协议 `agentdesk://app/` 加载，内容来自应用包内的 `Contents/Resources/Canvas/`；provider 图标来自 `agentdesk://app/icons/`。
- CSP 只允许同源脚本，`connect-src 'none'`；网页不能联网，也不能读本地文件。
- 页面内导航只允许 `agentdesk:`；回复里的 http(s) 链接交给系统默认浏览器打开。
- 网页只能发送有类型的指令（见 4.2），不能执行命令、指定路径或修改 provider 设置。
- Web Inspector 只在 Debug 构建中打开。

### 4.2 桥接协议 v1

网页 → Swift：`window.webkit.messageHandlers.agentDesk.postMessage({ type, ... })`

| type | 字段 | 作用 |
|---|---|---|
| `ready` | — | 网页加载完成，请求完整快照 |
| `board.create` / `board.select` / `board.rename` / `board.delete` | `boardID`、`title` | 管理画布；删除画布前先确认（`confirm.show`） |
| `node.create` | `boardID`、`provider`、`x`、`y`、`connectFrom?` | 新建对话节点；带 `connectFrom` 时同时连一条数据线 |
| `source.createFiles` | `boardID`、`x`、`y` | 打开原生文件面板，选中的文件放进新文件节点 |
| `source.addFiles` / `source.removeFile` | `boardID`、`nodeID`、`attachmentID` | 给文件节点添加文件（原生文件面板）或移除一个文件；都会换新版本 |
| `source.rename` | `boardID`、`nodeID`、`title` | 改资料节点的名称；空字符串恢复自动名称 |
| `source.rerunMCP` | `boardID`、`nodeID` | 打开 MCP 工作台并预填服务器、工具和参数；只有用户在工作台里按“运行工具”才调用 |
| `node.move` | `boardID`、`positions: [{nodeID, x, y}]` | 拖动结束后保存位置 |
| `node.delete` | `boardID`、`nodeIDs` | 删除节点（先确认） |
| `node.rename` | `sessionID`、`title` | 改名 |
| `node.branch` | `boardID`、`nodeID`、`messageID` | 从某条回复分支 |
| `edge.create` | `boardID`、`source`、`target` | 新建数据线（会拒绝自环、重复线、环路，以及连入资料节点） |
| `edge.delete` | `boardID`、`edgeIDs` | 删除连线 |
| `session.watch` | `sessionIDs` | 声明面板正在显示哪些会话，只有这些会话推送完整消息 |
| `chat.send` | `boardID`、`nodeID`、`text` | 发送；Swift 负责组装继承和上游内容 |
| `chat.stop` | `sessionID` | 停止 |
| `viewport.save` | `boardID`、`x`、`y`、`zoom` | 保存视口 |
| `clipboard.copy` | `text` | 复制到系统剪贴板 |
| `app.open` | `window: settings / classic / mcp`、`sessionID?` | 打开原生窗口；MCP 结果可以插回该会话的输入框，或“放到画布上”成为 MCP 结果节点 |
| `error.dismiss` | — | 关闭错误提示 |
| `session.setModel` / `session.setEffort` | `sessionID`、`modelID` / `effort` | 切换下一条消息的模型或推理档位（Cursor 档位换成同系列的模型 ID） |
| `node.merge` | `boardID`、`nodeIDs`、`provider`、`template: compare / summarize / critique` | 新建合流节点并连好数据线，模板放进输入框 |
| `node.rerun` | `boardID`、`nodeID` | 过期节点带上新输入重新回答（1 次调用） |
| `chain.downstream` / `chain.stop` | `boardID`、`nodeID` | 确认后按顺序重跑下游；停止正在进行的重跑 |
| `provider.refresh` | `provider` | 读取模型和档位列表（连接检查，不发起模型回合） |
| `attachment.choose` / `attachment.remove` | `sessionID`、`attachmentID` | 用原生文件面板添加文件，或移除待发送文件 |
| `confirm.answer` | `id`、`ok`、`checked?` | 回答 `confirm.show`；只有点击操作按钮时 `ok` 为 true；确认框带勾选项时 `checked` 是它的状态 |
| `node.mergeToBase` / `node.combine` / `node.revealWorktree` | `boardID`、`nodeID` | worktree（HARNESS.md H2）：确认后合并到基础分支；合流节点合并上游分支；在访达中显示 |
| `edge.setDiff` | `boardID`、`edgeID`、`ok` | 数据线是否附带上游分支的 diff 摘要 |
| `board.gitInit` | `boardID` | 确认后在项目文件夹里 `git init` 并做初始提交 |
| `notice.dismiss` | — | 关闭 `state.notice` 提示 |

Swift → 网页：`window.agentDesk.receive(payload)`

| type | 内容 |
|---|---|
| `snapshot` | 画布列表、当前画布（资料节点带 `source`：类型、名称、文件列表或 MCP 结果、是否正在导入）、全部会话摘要（标题、provider、模型、最后一条回复的预览、状态）、被关注会话的完整消息、运行状态、错误 |
| `patch` | 摘要变化、被关注会话的新增或替换消息、文字增量（`append`） |
| `composer.insert` | 把 MCP 结果插入某个节点的输入框 |
| `confirm.show` | `id`、`title`、`detail`、`action`、`checkbox?`：在页面内显示确认框（删除画布、删除节点、重跑下游、合并到基础分支、初始化 git）；`checkbox` 是可选的勾选项，例如“同时删除分支” |
| `state` 里的 `notice` 和节点的 `worktree` | 中性提示（合并完成、本轮只读）；节点的 worktree 分支、基础分支、路径、是否已清理 |
| `state` 里的 `models` / `quotas` / `drafts` | 各 provider 的模型选项、额度窗口、被关注会话的待发送文件 |

文件拖放：原生层收到拖进窗口的文件后，调用页面的 `window.agentDesk.dropTarget(x, y)` 问落点是什么（`panel` / `source` / `canvas` 及画布坐标 / `none`），页面不会拿到文件路径或内容。“放到画布上”用 `window.agentDesk.viewCenter()` 取当前视图中心作为新节点位置。

确认框：删除和会花调用次数的操作（`board.delete`、`node.delete`、`chain.downstream`）不会直接执行。Swift 记下待执行的操作并发出 `confirm.show`；页面显示确认框，焦点默认在“取消”，Esc、取消和点击遮罩都会回答 `ok: false`，只有点击操作按钮才回答 `ok: true`。Swift 只执行自己发出且尚未回答过的 `id`，每个 `id` 只执行一次；页面重新加载（再次发送 `ready`）时，所有未回答的确认都视为取消。

推送合并：Swift 监听模型变化，每 33ms 最多推一次；流式输出时只发增量文字，不发整段历史。图片和附件不走这条通道。

## 5. 调用预算

- 每次发送只调用一次，没有自动重试或隐藏调用。
- 第二阶段的“运行全部”“重跑下游”“运行草稿”，执行前都会显示要调用几次，用户点击后才执行，并沿用讨论室的上限（单次最多 12 次调用）。
- 模型建议的子目标只生成草稿节点，不会自己启动。

## 8. 第一轮画布交互（0.6.0）

展开状态是当前窗口的阅读状态；位置与会话仍由 Swift 保存。展开节点与面板共同声明要读取的会话，`session.watch.panelSessionID` 单独指定文件拖放与额度查询的目标，展开节点不会改变它。保留原有最多 8 个完整会话的订阅上限：面板与父节点优先，画布最多同时展开 6 张卡片，第七张收起最早展开的一张。

新增桥接命令：
- `node.quote { boardID, nodeID, messageID }`：独立会话，仅引用指定完整回复；数据线沿用 `sourceMessageID` 保存消息主键，无此字段的数据线继续跟随最新回复。
- `board.search { boardID, text, id }` → `search.results { boardID, query, id, hits: [{nodeID, messageID?, excerpt}] }`：Swift 搜索完整本地记录，请求 ID 用于丢弃迟到结果。
- `context.preview { boardID, nodeID, text, id }` → `context.preview { nodeID, id, text, notes }`：复用发送路径的文字与附件组装，只读取状态。前端提供刷新；原生分叉与官方已有历史通过说明单独展示。

节点摘要增加 `latestReplyID`，用于明确分支与引用的完整回复；展开时才订阅完整记录。搜索定位打开完整历史并高亮命中消息，不通过加载整个画布的完整历史实现搜索。

## 9. 画布整理（0.7.0）

- `CanvasGroup { id, title, nodeIDs }` 存在 `CanvasBoard.groups` 中，旧文件缺少字段时按空数组读取。每个节点最多属于一个组；空组自动清理。对话、文件和 MCP 节点均可分组。分组不改变上下文或资料内容。
- 分组框依据成员位置与当前卡片尺寸计算；节点始终保存绝对坐标，拖动组标题最终提交一次 `node.move`，因此整组移动只占一步撤销。
- `board.layout { boardID, sizes: [{ nodeID, width, height }] }`：先排组内节点，再排组和独立节点。按依赖分层、同层竖排，独立节点或独立分组使用网格，预留展开卡片尺寸。组间出现循环时按保存顺序处理，保证完成与互不覆盖。`fitBoardID` 在布局后请求前端适应视口。
- `group.create / group.add { boardID, nodeIDs, groupID? }`，`group.rename { boardID, groupID, title }`，`group.dissolve { boardID, groupID }`。
- `board.undo / board.redo { boardID }`：原生层按画布保存最多 100 步本次启动内的编辑。快照仅包含位置、分组与连线，不存会话内容或视口。撤销/重做保留连线当前的投递版本及原生分叉状态，避免把已投递资料再次当作新输入。新增/删除节点时清空受影响画布的编辑历史。
- 小地图复用 React Flow 的 MiniMap，支持拖动平移和滚动缩放。分组只作为背景框显示，搜索、连接和会话操作继续定位真实节点。
